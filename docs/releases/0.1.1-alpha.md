# MIRulesets 0.1.1-alpha

Исправления после первого предварительного выпуска. Тег — `v0.1.1-alpha`; версия приложения — `0.1.1-alpha`.

## Изменения

1. **Кеширование панели.** Встроенные HTML, JavaScript, CSS, шрифты и другие статические файлы получают `ETag` по SHA-256 содержимого. Повторный запрос с актуальным `If-None-Match` возвращает `304` без тела; браузеру не требуется заново скачивать неизменившиеся файлы. Проверка актуальности сохраняется через `Cache-Control: no-cache`.
2. **Лицензия MIT.** Добавлен `LICENSE` в исходники и упаковку релизных архивов; контейнер содержит его по пути `/LICENSE`. Уведомление MIBoard и лицензии шрифтов сохранены в `web/licenses`.
3. **Go 1.26.3.** Релизный workflow использует ту же версию Go, что CI и Docker. В `go.mod` указан `toolchain go1.26.3`.
4. **Версия загрузчика.** Стандартный `User-Agent` источников использует фактическую версию сборки из той же переменной, что CLI и API.
5. **Документация.** Уточнены точные исключения, поведение webhook и обновление зависимых наборов через `ruleset://`.

## Архивы и контейнер

Workflow для тега настроен на сборку шести архивов и файла контрольных сумм `SHA256SUMS`:

| Платформа | Архитектуры | Имена архивов |
| --- | --- | --- |
| Linux | amd64, arm64 | `mirulesets_v0.1.1-alpha_linux_<arch>.tar.gz` |
| macOS | amd64, arm64 | `mirulesets_v0.1.1-alpha_darwin_<arch>.tar.gz` |
| Windows | amd64, arm64 | `mirulesets_v0.1.1-alpha_windows_<arch>.zip` |

Целевой образ — `ghcr.io/blagodaren/mirulesets:0.1.1-alpha` для Linux amd64/arm64. После успешного workflow файлы доступны на [странице выпуска](https://github.com/blagodaren/mirulesets/releases/tag/v0.1.1-alpha); суффикс `alpha` означает prerelease.

Проверка скачанных архивов в Linux: `sha256sum -c SHA256SUMS`; в macOS: `shasum -a 256 -c SHA256SUMS`. В PowerShell сравните `Get-FileHash <архив> -Algorithm SHA256` со строкой этого архива в `SHA256SUMS`.

## Обновление

Перед заменой бинарника или контейнера остановите приложение и сохраните весь каталог данных. Экспорт из панели не содержит секретов и истории. Используйте прежний каталог или Docker-том с новым выпуском; несколько процессов не должны обращаться к нему одновременно. [Порядок обновления и резервного копирования](https://github.com/blagodaren/mirulesets/blob/v0.1.1-alpha/docs/deployment.md#данные-обновления-и-проверка).

После запуска проверьте `mirulesets version`: ожидается `MIRulesets 0.1.1-alpha`.

## Сохраняющиеся ограничения

Это предварительный выпуск. [Ограничения 0.1.0-alpha](https://github.com/blagodaren/mirulesets/blob/v0.1.1-alpha/docs/releases/0.1.0-alpha.md#ограничения) остаются в силе, в том числе:

1. Предпросмотр принимает `auto`, YAML, text и MRS без пользовательских заголовков и фильтров источника.
2. Исключения удаляют только полностью совпавшие нормализованные правила: поддомен не вычитается из `+.example.com`, подсеть — из более широкого CIDR.
3. Ссылки `/rules/<id>.*` доступны без токена; публикация нескольких файлов в S3 неатомарна.
4. Webhook отправляется при каждой неудачной попытке, без объединения одинаковых ошибок и сообщения о восстановлении.
5. Публикация источника `ruleset://id` не запускает пересборку зависимых наборов. Изменения попадут в них при следующей плановой или ручной сборке.
