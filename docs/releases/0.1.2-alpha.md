# MIRulesets 0.1.2-alpha

Исправления настройки внешнего HTTPS и проверки версии в CI. Тег — `v0.1.2-alpha`; версия приложения — `0.1.2-alpha`.

## Изменения

1. **Предупреждение о прокси.** При `MI_PUBLIC_URL=https://…`, `MI_TLS_MODE=off` и пустом `MI_TRUSTED_PROXIES` сервер записывает предупреждение при запуске в стандартный лог и журнал событий. Пользователи за одним прокси видны с одним IP, поэтому неудачные попытки одного пользователя могут заблокировать вход всем. Настройте `MI_TRUSTED_PROXIES` только для адресов доверенного прокси: `/32` для отдельного IPv4 или `/128` для IPv6. Предупреждение не меняет лимит попыток и не включает доверие к `X-Forwarded-For` автоматически.
2. **Версия контейнера в CI.** Workflow получает версию из CLI собранного бинарника, использующего `internal/version/version.go`, и передаёт её в сборку контейнера и проверку результата. Дублирующие константы версии приложения удалены из CI.

## Архивы и контейнер

Workflow для тега настроен на сборку шести архивов и файла контрольных сумм `SHA256SUMS`:

| Платформа | Архитектуры | Имена архивов |
| --- | --- | --- |
| Linux | amd64, arm64 | `mirulesets_v0.1.2-alpha_linux_<arch>.tar.gz` |
| macOS | amd64, arm64 | `mirulesets_v0.1.2-alpha_darwin_<arch>.tar.gz` |
| Windows | amd64, arm64 | `mirulesets_v0.1.2-alpha_windows_<arch>.zip` |

Целевой образ — `ghcr.io/blagodaren/mirulesets:0.1.2-alpha` для Linux amd64/arm64. После успешного workflow файлы доступны на [странице выпуска](https://github.com/blagodaren/mirulesets/releases/tag/v0.1.2-alpha); выпуск помечается как prerelease.

Проверка скачанных архивов в Linux: `sha256sum -c SHA256SUMS`; в macOS: `shasum -a 256 -c SHA256SUMS`. В PowerShell сравните `Get-FileHash <архив> -Algorithm SHA256` со строкой этого архива в `SHA256SUMS`.

## Обновление

Перед заменой бинарника или контейнера остановите приложение и сохраните весь каталог данных. Экспорт из панели не содержит секретов и истории. Используйте прежний каталог или Docker-том с новым выпуском; несколько процессов не должны обращаться к нему одновременно. [Порядок обновления и резервного копирования](https://github.com/blagodaren/mirulesets/blob/v0.1.2-alpha/docs/deployment.md#данные-обновления-и-проверка).

После запуска проверьте `mirulesets version`: ожидается `MIRulesets 0.1.2-alpha`. Если появилось предупреждение о прокси, настройте доверенные адреса по [руководству развёртывания](https://github.com/blagodaren/mirulesets/blob/v0.1.2-alpha/docs/deployment.md#внешний-nginx).

## Сохраняющиеся ограничения

Это предварительный выпуск. [Прежние ограничения](https://github.com/blagodaren/mirulesets/blob/v0.1.2-alpha/docs/releases/0.1.0-alpha.md#ограничения) сохраняются: ограниченный предпросмотр источников, только точные исключения, открытые ссылки `/rules/<id>.*`, неатомарная публикация S3, повторяющиеся webhook без сообщения о восстановлении и отсутствие автоматической пересборки зависимых наборов `ruleset://`.
