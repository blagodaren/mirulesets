# Журнал событий и оповещения

Задайте `MI_ALERT_WEBHOOK_URL` в `.env`, чтобы получать JSON-уведомления об ошибках сборки. Без этой переменной журнал работает, а внешние запросы не выполняются.

```dotenv
MI_ALERT_WEBHOOK_URL=https://hooks.example.com/mirulesets
MI_ALERT_WEBHOOK_TOKEN=
```

`MI_ALERT_WEBHOOK_TOKEN` необязателен: при заполнении отправляется заголовок `Authorization: Bearer <token>`. URL допускает query-параметры, но не userinfo или fragment. Для удалённого получателя используйте HTTPS. После изменения окружения пересоздайте контейнер: `docker compose up -d`.

Получатель должен принимать POST с `Content-Type: application/json`:

```json
{
  "time": "2026-11-12T10:00:00Z",
  "level": "error",
  "message": "источник 1: HTTP 503",
  "rulesetId": "telegram-ip"
}
```

Отправляется одно уведомление на каждую ошибку сборки, в том числе на частичный сбой публикации в S3. Успешные сборки не вызывают webhook. На доставку отводится не более 5 секунд; переходы по HTTP-редиректам запрещены. Ответ `2xx` считается успешным. Повторной доставки после сетевого сбоя или перезапуска нет: следующая неудачная сборка создаст новое уведомление. Это оповещение дополняет журнал, а не заменяет надёжную очередь доставки.

Ошибка webhook записывается как событие `warning` и в стандартный журнал процесса. Текст ответа получателя, URL webhook и bearer-токен в эту ошибку не попадают. Ошибка доставки не меняет результат сборки и не создаёт рекурсивных оповещений.

События сохраняются в `<MI_DATA_DIR>/events.jsonl` в формате JSON Lines. Каждая запись синхронно сбрасывается на диск; права новых файлов — `0600`. При достижении 1 MiB файл перемещается в `events.jsonl.1`, заменяя предыдущий архив. Общий объём двух файлов ограничен 2 MiB. Длинные сообщения сокращаются до 16 KiB текста с отметкой о сокращении.

При старте приложение восстанавливает последние 100 доступных событий из обоих файлов. Оборванная последняя строка после аварийного завершения отбрасывается перед следующей записью. Повреждённая завершённая JSON-строка вызывает ошибку старта с именем файла. В памяти всегда остаются последние 100 событий, доступные через API событий; UI может отображать только часть этого списка. Ошибка записи на диск выводится в стандартный журнал, а событие остаётся в памяти до перезапуска.


## Метрики Prometheus

Задайте `MI_METRICS_TOKEN` длиной от 32 символов без переводов строк; значение должно отличаться от `MI_API_TOKEN`. Этот токен разрешает только чтение `/metrics` и не открывает административный API. Сессия панели и `MI_API_TOKEN` по-прежнему принимаются; если отдельный токен не задан, прежнее поведение сохраняется.

Сохраните значение `MI_METRICS_TOKEN` в файле `/etc/prometheus/secrets/mirulesets-token`, доступном процессу Prometheus, и добавьте scrape-конфигурацию:

```yaml
scrape_configs:
  - job_name: mirulesets
    scheme: https
    metrics_path: /metrics
    authorization:
      type: Bearer
      credentials_file: /etc/prometheus/secrets/mirulesets-token
    static_configs:
      - targets: [rules.example.com]
```

Для локальной проверки используйте `scheme: http` и адрес локального сервера. Проверка границы доступа: запрос `/metrics` с этим Bearer-токеном возвращает 200, а `/api/rulesets` — 401. `/healthz` остаётся публичным. [Описание метрик](deployment.md#prometheus).
