# Управление наборами правил

Настройки источников и своих правил находятся в редакторе набора; опубликованные файлы и состояние сборки — в его карточке. Поиск адресов, общий YAML и перенос настроек доступны на странице «Инструменты».

## Надёжность сборок

1. **Защита от падения числа правил.** `maxDropPercent` задаёт допустимое уменьшение относительно последней опубликованной сборки. По умолчанию 50%; 0 запрещает любое уменьшение, 100 отключает проверку. Ровно порог допустим. Проверка выполняется после нормализации, объединения и исключений, до записи нового поколения и PUT в S3. При превышении сохраняются прежние файлы; ошибка и новый статус источников видны в панели. Для первой сборки базы сравнения нет. Порог падения применяется только при неизменной ревизии конфигурации; после редактирования следующая сборка допускает сокращение правил, а diff рассчитывается всегда.
2. **Diff.** Карточка и журнал показывают добавленные/удалённые нормализованные строки. Перестановка строк не считается добавлением или удалением. Первое поколение показывает все правила как добавленные.
3. **Откат.** Кнопка выбирает предыдущее сохранённое поколение и проверяет SHA-256 его файлов. Повторное нажатие возвращает поколение до отката. Новые метаданные хранятся в `build.json`, правила для сравнения — в `canonical.json` с проверкой сохранённого SHA-256; старые поколения без метаданных доступны для отката после первой изменившейся сборки новой версией. После отката плановые пересборки удерживаются до нажатия «Возобновить обновления», ручной сборки, сохранения набора или изменения его конфигурации через импорт; повторная отправка S3 остаётся доступной. Старые состояния с `rollbackUntil` сохраняют прежнюю паузу до указанного времени. При S3 предыдущие байты также отправляются в bucket.
4. **Статус каждого источника.** Сохраняются время проверки, последней успешной загрузки, число правил после фильтра, HTTP 200/304 и ошибка. `ruleset://` и S3 не получают искусственный HTTP-статус.
5. **Повтор S3.** Кнопка отправляет только неуспешные форматы из уже готовых локальных файлов. Источники не загружаются и поколение не меняется. Фоновое повторение ошибок S3 использует тот же путь с backoff. Перед перезаписью стабильных S3-ключей на диске отмечается незавершённая отправка: отмена/сбой процесса не позволяет ошибочно пропустить восстановление.

Публикация нескольких объектов S3 остаётся неатомарной; локальная публикация переключается целиком. Проверка порога сравнивает общее число правил: потерю одного источника, перекрытую ростом другого, она не выявляет.

## Источники

Предпросмотр по URL доступен для HTTP(S)/S3 и значений формата `auto`, `yaml`, `text`, `mrs`. Он показывает нормализованные правила источника до объединения со своими правилами и применения исключений. Фильтры источника, категории DAT и пользовательские HTTP-заголовки не применяются; внутренние ссылки `ruleset://`, ASN и остальные явно выбранные форматы проверяются при сборке. [Порядок предпросмотра и лимиты](deployment.md#предпросмотр-источника).

1. **Заголовки и токены.** Поле заголовков принимает по одной паре `Имя: значение`, например `Authorization: Bearer ...`. Значения хранятся только в серверном `state.json` с ограниченными файловыми правами. API и экспорт показывают только имена заголовков. Пустое поле при редактировании сохраняет старые значения; отдельный флажок их удаляет. Изменение URL не переносит старые секреты на новый адрес. При редиректе на другой origin пользовательские заголовки снимаются; HTTP-кэш различает авторизацию. Файл данных и его резервные копии содержат секреты, поэтому доступ к ним должен быть ограничен.
2. **Внутренний набор.** `ruleset://example-domains` читает последнее опубликованное поколение без HTTP. Зависимость должна существовать и быть собрана. Циклы и удаление используемого набора запрещены, включая выключенные ссылки. Сборка зависимостей автоматически не запускается. Публикация источника также не запускает пересборку использующего его набора: новое поколение попадёт в него при следующей плановой или ручной сборке.
3. **Форматы.** `geosite`, `geoip`, `hosts`, `adblock`, `singbox` доступны в выборе источника. Для DAT укажите selector категории/страны (`google`, `cn,us`); `*` явно выбирает всё. Adblock поддерживает DNS-подмножество: домены и `||example.com^`. Исключения, URL-фильтры и косметика отклоняются, поскольку их нельзя перенести в положительный доменный набор без изменения смысла. [Матрица и ограничения кодеков](../internal/rules/README.md).
4. **ASN.** Выберите формат `asn`, адрес `AS13335`, behavior `ipcidr` или `classical`. Источник — originating-префиксы IPv4/IPv6 последнего снимка [RIPEstat RIS Prefixes](https://stat.ripe.net/docs/data-api/api-endpoints/ris-prefixes), снимки 00/08/16 UTC. Это наблюдаемые BGP-префиксы, а не гарантия полноты всех сетей владельца ASN. Пустые и несогласованные ответы отклоняются.
5. **Фильтры.** `includeRegex` оставляет совпавшие строки, `excludeRegex` затем удаляет совпадения. Используется RE2, до 4096 байт на выражение. Фильтруются нормализованные правила источника до объединения.

Исключения набора удаляют только полностью совпавшие нормализованные правила: `sub.example.com` не вычитается из `+.example.com`, а подсеть — из более широкого CIDR. Для такого вычитания исходные правила нужно заранее разделить.

## Форматы и клиенты

1. **sing-box.** Выход `singbox` создаёт `.json`, `srs` — `.srs` version 2. Совместимость проверена официальным sing-box 1.14.1. Условия classical, которые sing-box не может представить эквивалентно, приводят к ошибке всей сборки.
2. **Общий snippet.** «Инструменты → Все наборы для Mihomo» создаёт YAML с `rule-providers` и `RULE-SET`. Можно выбрать единую политику или оставить политики каждого набора. Включаются опубликованные актуальные наборы с подходящим форматом; пропуски перечисляются.
3. **Проверка адреса.** Поиск домена или IP выполняется по опубликованным поколениям без DNS-запросов. Отображаются совпавшие строки. Classical-условия, которым нужны данные о процессе, соединении или внешние базы, отмечаются как непроверенные. До 100 строк-примеров на набор; общий счётчик совпадений не обрезается.
4. **Скачивания.** Карточки и `mirulesets_downloads_total{ruleset="..."}` показывают успешные GET-ответы 200/206. HEAD, 304 и ошибки не увеличивают счётчик. Счётчики обнуляются при перезапуске процесса; прямые запросы к S3/CDN приложению не видны.

## Администрирование

1. **Экспорт/импорт.** «Инструменты» скачивает конфигурацию в формате `state.json`, без секретов, истории и локальных путей поколений. Импорт атомарно добавляет/обновляет перечисленные наборы; остальные остаются. Для существующего ID требуется актуальная `revision`, сохранённые серверные заголовки сохраняются по ID источника. Ошибка одного набора отменяет весь импорт. Это перенос настроек, а не полная резервная копия каталога данных.
2. **Декларативный YAML.** Задайте `MI_RULESETS_FILE=/etc/mirulesets/rulesets.yml`. [Пример](../deploy/rulesets.example.yml) использует те же camelCase-поля, что API. При старте файл атомарно объединяется с состоянием; перечисленные настройки имеют приоритет. Неизменённый файл не повышает ревизии. Отсутствующие в файле наборы не удаляются. В Docker файл нужно отдельно примонтировать; не храните токены в публичном Git.
3. **Клонирование, поиск, теги.** Клон копирует настройки и серверные заголовки, но не опубликованную сборку. Поиск работает по имени, ID и тегам. До 20 тегов длиной до 64 байт.
4. **Релизы.** [.github/workflows/release.yml](../.github/workflows/release.yml) запускается по тегам `vX.Y.Z` / `vX.Y.Z-prerelease`: тесты с race detector, vet, бинарники Linux/macOS/Windows для amd64/arm64, SHA256SUMS, GitHub Release и GHCR-образ linux/amd64+arm64. Версия встраивается через `-ldflags`. Публикация запускается отправкой тега в GitHub; готовые образы доступны в `ghcr.io/blagodaren/mirulesets`. Настройка следует [документации GitHub](https://docs.github.com/en/actions/tutorials/publish-packages/publish-docker-images).
5. **Удаление S3.** Удаление набора ставит в устойчивую очередь удаление пяти известных ключей `<prefix>/<id>.{yaml,txt,mrs,json,srs}`. При сбое очередь повторяется после перезапуска и по расписанию. Очередь привязана к исходному S3 endpoint/bucket/prefix: при смене цели очистка останавливается до восстановления прежних настроек. До завершения очистки тот же ID нельзя создать повторно. Требуется `DeleteObject`; в versioned bucket удаление текущего ключа создаёт delete marker, исторические версии регулируются lifecycle-политикой bucket. Уже закэшированные CDN-копии исчезают по правилам CDN.

## API

| Запрос | Действие |
| --- | --- |
| `POST /api/rulesets/{id}/rollback` | Переключить поколение и удерживать откат |
| `POST /api/rulesets/{id}/resume` | Снять удержание без немедленной сборки |
| `POST /api/rulesets/{id}/retry-s3` | Повторить неудачные отправки |
| `POST /api/rulesets/{id}/clone` с `{ "id": "copy", "name": "Copy" }` | Клонировать настройки |
| `GET /api/config`, `POST /api/config` | Экспорт/атомарный импорт |
| `GET /api/snippet?policy=PROXY` | Общий YAML |
| `GET /api/lookup?query=example.com` | Найти совпадения |

API требует существующей сессии с CSRF или серверного Bearer-токена, как остальные административные действия.

## Проверка

```sh
go test ./...
go vet ./...
node --check web/app.js
```

Тесты охватывают границу порога, сохранение last-good, diff, откат/повторный откат и паузу планировщика, отдельные повторы S3, очистку, атомарный импорт, неизменность декларативного состояния, отсутствие секретов в API, циклы, кэш с авторизацией, статусы и новые кодеки. Проверки S3 выполняются с HTTP-стендом, а не с production bucket.
