MIRulesets объединяет источники и собственные правила, проверяет результат и публикует готовые файлы по постоянным ссылкам. Сервер, веб-панель и конвертер работают в одном контейнере.

> [!NOTE]
> **0.1.0-alpha — предварительная версия.** [Состав выпуска и ограничения](docs/releases/0.1.0-alpha.md). Перед обновлением сохраняйте весь каталог данных; экспорт настроек из панели не заменяет резервную копию.

## Возможности

| Раздел | Что можно сделать |
| --- | --- |
| **Источники** | Объединить HTTP(S), S3 и другие наборы; задать приватные заголовки, фильтры, свои правила и исключения |
| **Сборки** | Обновлять по расписанию, блокировать резкое падение числа правил, видеть diff и статусы источников |
| **Публикация** | Раздавать файлы локально и через S3, повторять неудачные отправки, откатываться на предыдущее поколение |
| **Клиенты** | Получить общий YAML для Mihomo, проверить попадание домена/IP в наборы, посмотреть число скачиваний |
| **Управление** | Клонировать наборы, искать по тегам, переносить настройки, применять YAML при старте, собирать метрики |

## Установка на сервер

Нужен Linux-сервер с Docker. Готовый образ `ghcr.io/blagodaren/mirulesets:0.1.0-alpha` поддерживает amd64 и arm64; собирать приложение на сервере не требуется.

**1. Подготовьте каталог настроек.**

```sh
mkdir mirulesets
cd mirulesets
curl -fsSLo .env https://raw.githubusercontent.com/blagodaren/mirulesets/v0.1.0-alpha/.env.example
chmod 600 .env
```

**2. Задайте пароль администратора.**

```sh
openssl rand -hex 24
nano .env
```

Запишите полученный пароль в `MI_ADMIN_PASSWORD`. Для первого входа через SSH-туннель оставьте исходный `MI_PUBLIC_URL=http://localhost:8080`. HTTPS-адрес задайте при подключении прокси или встроенного TLS.

**3. Запустите контейнер.**

```sh
docker run -d --name mirulesets --restart unless-stopped \
  --env-file .env --read-only --tmpfs /tmp:size=64m,mode=1777 \
  --cap-drop ALL --security-opt no-new-privileges:true --stop-timeout 30 \
  -p 127.0.0.1:8080:8080 -v mirulesets-data:/data \
  ghcr.io/blagodaren/mirulesets:0.1.0-alpha
```

Данные сохраняются в томе `mirulesets-data`; контейнер работает от UID/GID `10001:10001`. Порт доступен только на сервере. Для первого входа откройте SSH-туннель со своего компьютера:

```sh
ssh -L 8080:127.0.0.1:8080 user@your-vps
```

Откройте [http://127.0.0.1:8080](http://127.0.0.1:8080) в браузере. Создайте набор, добавьте источники или свои правила и нажмите «Собрать». Готовые файлы и конфигурация Mihomo появятся в карточке набора.

Для постоянного доступа настройте HTTPS: [nginx](docs/deployment.md#внешний-nginx), [Caddy](docs/deployment.md#caddy-на-vps), [Nginx Proxy Manager](docs/deployment.md#nginx-proxy-manager-или-caddy-в-docker) или [встроенный ACME](docs/deployment.md#автоматический-сертификат-без-nginx). [S3 и резервные копии →](docs/deployment.md)

## Форматы

| Направление | Форматы |
| --- | --- |
| **Импорт** | YAML, text, MRS, geosite/geoip DAT, hosts, DNS-подмножество Adblock, sing-box JSON; ASN → CIDR |
| **Экспорт** | YAML, text, MRS, sing-box JSON и SRS |

Поддерживаются `domain`, `ipcidr` и `classical`. MRS не поддерживает `classical`; преобразования без эквивалентного результата отклоняются. [Матрица совместимости и ограничения](internal/rules/README.md).

Локальная публикация переключает целое поколение атомарно. При ошибке источника прежние файлы остаются доступны; S3 обновляет объекты по отдельности. Ссылки на файлы открыты клиентам без пароля панели — для приватных правил настройте внешний контроль доступа.
